`@plutocms/nuxt-content` is a layer for sites that use [Nuxt Content](https://content.nuxt.com). Pluto edits the Markdown files. Nuxt Content reads the same files to build the public site.

This documentation site uses the layer. Its pages are Markdown files in a GitHub repository. Editors change them in the Pluto admin, in standalone mode with no database.

## What the layer gives

- A `docs` page type. It maps the frontmatter of a Nuxt Content page to form fields.
- Nested, numbered folders. `content/1.getting-started/2.installation.md` is one item. The list shows the pages in tree order.
- A source editor for MDC, the Markdown syntax with components. Its **Insert** menu adds snippets: note, tip, code group, tabs, steps, cards, and more.
- A **View page** button in the admin form. It shows in edit mode only, because a new page has no public route yet. It opens the page in a new tab.
- `usePlutoContentEditLink(page, type = 'doc')`: an "Edit in admin" link on the public page, for signed-in staff only. It gives `null` for everyone else. The link appears after hydration.
- A CSS offset that keeps the Nuxt UI header and the sticky sidebar below the Pluto admin bar.
- English and Brazilian Portuguese text.

The layer extends `@plutocms/pluto`. Your app extends only `@plutocms/nuxt-content`. Do not add `@plutocms/pluto` to `extends`.

## The docs page type

The `docs` preset makes one content type for the pages of a Nuxt Content site.

- Items are nested Markdown files. The id is the path under `source`, without `.md`, such as `2.core/03.content-model`.
- A page has no draft state and no stored dates: `status` and `timestamps` are off.
- The list sorts by id in tree order: `index` first, then the numeric prefixes as numbers.
- The capabilities are `docs:write` and `docs:delete`. There is no read capability.
- The form uses the focus layout with the full width.

| Field | Frontmatter key | Region |
| --- | --- | --- |
| Title (required) | `title` | Main |
| Slug (required). It holds the whole path. | None. It is the file path. | Main |
| Description | `description` | Main |
| Body. A source editor with `widget: 'mdc'`. | None. It is the file body. | Main |
| Navigation title | `navigation.title` | Side |
| Navigation icon | `navigation.icon` | Side |
| Hidden in navigation | `navigation: false` | Side |
| SEO title | `seo.title` | Side |
| SEO description | `seo.description` | Side |

A save writes the flat fields back into `navigation` and `seo`. Other keys stay as the author wrote them, for example `navigation.badge`, `seo.ogImage`, and `links`. A hidden page writes `navigation: false`, which replaces its navigation title and icon. A save that changes nothing makes no commit.

## Requirements

- `@plutocms/pluto` 0.19 or newer.
- Node 22.5 or newer. The layer sets the native SQLite connector of Nuxt Content.

## Installation

::steps
### Add the layer

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [['@plutocms/nuxt-content', { install: true }]],

  plutoCms: {
    enabled: true,
    storage: process.env.NODE_ENV === 'production' ? 'github' : 'fs',
    github: { repo: 'my-org/my-docs', branch: 'main', appSlug: process.env.PLUTO_CMS_APP_SLUG },
    dir: 'content',
    postType: false,
  },

  plutoNuxtContent: {
    types: [{ preset: 'docs', name: 'doc', source: '' }],
  },
})
```

### Define the collections

Define the collections in `content.config.ts`, as for any Nuxt Content site. The layer defines no collection.

### Start the CSS entry

```css [app/assets/css/main.css]
@import 'tailwindcss';
@import '@nuxt/ui';
@import '#build/pluto.css';
```

### Use PlutoRoot

Use `PlutoRoot` in `app.vue` instead of `UApp`. Render the admin routes (`/admin/**`) with only `<NuxtPage />`. Render the public routes with your own header, main and footer. `PlutoRoot` renders a `NuxtLayout`, so do not use a page layout for the docs sidebar. Put the sidebar in a component.

### Offset the site header

Give the class `pluto-header-offset` to the `UHeader` of the site. The layer then keeps the header, the page aside, and the table of contents under the admin bar. The variable `--pluto-site-header-height` is the height of your header. The default is `4rem`. See [Offset your header for the admin bar](/github-cms/public-read#offset-your-header-for-the-admin-bar).

### Set the GitHub App secrets

See [GitHub App](/github-cms/github-app).
::

::note
The layer sets the Pluto defaults `eslint.config.standalone: false` and the size `xl` for buttons, inputs, and form fields. A site with its own ESLint config or the Nuxt UI default sizes sets them back in its own config.
::

## Options

`plutoNuxtContent.types` is a list. Each entry has these options:

| Option        | Description                                                                  |
| ------------- | ---------------------------------------------------------------------------- |
| `preset`      | The preset. Only `docs` exists.                                              |
| `name`        | The content type name. The admin URL is `/admin/content/<name>`.             |
| `source`      | The folder under the CMS content dir. Use `''` for the content dir itself.   |
| `label`       | The singular label. The default is `Page`.                                   |
| `labelPlural` | The plural label. The default is `Pages`.                                    |
| `exclude`     | Ids to hide: an id (`index`), or a folder with a trailing slash (`drafts/`). |
| `routePrefix` | The route prefix of the pages on the public site. The default is none.       |

- `name` uses lowercase letters, numbers, and dashes. It starts with a letter. It is unique.
- `source` is `''` or a nested folder path, such as `1.docs/api`.
- A type with a problem is dropped, and the module logs one error for it.

The layer is off, with an error in the log, when `plutoCms.enabled` is not `true`.

To test an unpublished checkout, point `extends` at the local folder of the layer. The docs site reads `PLUTO_NUXT_CONTENT_PATH` for this.

::note
The layer sets `plutoCms.commit.skipDeploy` to `false`. Nuxt Content builds the content at build time, so each edit must start a new deploy.
::
