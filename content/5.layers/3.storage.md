::warning
`@plutocms/supabase-storage` is retired. Do not install it. The [media library](/core/media) is in core now, and `@plutocms/supabase` gives its Supabase driver.
::

The media library is the same for every backend: one Media page, one `media` field widget, one picker. A backend layer gives only the storage. On Supabase, the files are in Supabase Storage (the `media` bucket) and the records are in the `media` table. Both are the same as before, so the files of the old layer stay.

## Move an app

1. Remove `@plutocms/supabase-storage` from `extends` and from `package.json`. Keep `@plutocms/supabase` (or a layer that extends it).
2. Update `@plutocms/supabase` to 0.16 or later. Start the app. The migration `009_media.sql` adds the columns `bucket`, `width` and `height` to `media`. It fills in the type and the size of each file from Supabase Storage.
3. Open the Media page (`/admin/media`) and select **Fill in missing image sizes**.
4. In your code, replace the routes `/api/_pluto/storage/media` with `/api/_pluto/media`, and `useMedia()` with `usePlutoMedia()`. A media field stores the id of a record as text.

The capabilities `media:manage` and `media:delete` do not change.
