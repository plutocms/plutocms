A Pluto project is a Nuxt app. It extends one or more layers.

## The blog template

The blog template works with both backends: the GitHub CMS (no database) and Supabase. With the GitHub CMS, it has these files:

```text
.
├─ app/
│  ├─ assets/css/tailwind.css
│  ├─ components/
│  │  ├─ LanguageSwitch.vue
│  │  ├─ PlutoPostPreview.vue
│  │  ├─ PostArticle.vue
│  │  └─ PostCard.vue
│  ├─ layouts/default.vue
│  ├─ pages/
│  │  ├─ index.vue
│  │  └─ posts/[slug].vue
│  ├─ app.config.ts
│  ├─ app.vue
│  └─ error.vue
├─ content/
│  └─ posts/
│     ├─ hello-world.md
│     └─ pluto-works-out-of-the-box.md
├─ i18n/locales/
│  ├─ en.json
│  └─ pt-BR.json
├─ nuxt.config.ts
├─ package.json
├─ README.md
└─ tsconfig.json
```

- `content/posts/` holds the posts as Markdown files (GitHub CMS only).
- `app/pages/` holds the public pages. They read posts from the [Public API](/docs/core/public-api) with `usePlutoPublicList` and `usePlutoPublicItem`.
- `app/components/PostArticle.vue` renders one post, with the core component `PlutoHtml` for the body. The post page and the preview of the post editor (`PlutoPostPreview.vue`) both use it.
- `app/app.config.ts` sets the colors, and `tailwind.css` imports the [Pluto site theme](/docs/core/styles#the-pluto-site-theme).
- `i18n/locales/` holds the texts of the site, one file per language.
- `nuxt.config.ts` extends `@plutocms/core` and, when needed, sets the `plutoGithub` options.
- `package.json` lists `@plutocms/core`, `nuxt`, `vue`, and `vue-router`. No other layer is needed.

With Supabase, three things differ, and the CLI sets them:

- `nuxt.config.ts` extends `@plutocms/supabase-blog`. That layer brings `@plutocms/supabase` and core.
- `package.json` also lists `@plutocms/supabase-blog`, and has the `supabase-types` script.
- There is no `content/` folder: the posts are in the database.

The pages link to a post by its slug (`/posts/<slug>`), the same for both backends.

The template has no `.env` file. The CLI writes it when you create the project. With the GitHub CMS, **Create the GitHub App** in the admin gives the GitHub App values. See [Quickstart](/docs/github-cms/quickstart).

## The shop template

The shop template (Supabase) has these folders:

- `app/` with `app.vue`, layouts, a `Navbar.vue` component, and the public pages.
- `app/assets/css/tailwind.css`, the CSS entry of the app.
- `public/`, with a favicon and `robots.txt`.

Its `nuxt.config.ts` extends one layer only: `@plutocms/supabase-shop`. That layer brings `@plutocms/supabase` and the other layers below it. The `package.json` lists that layer, `nuxt`, `vue`, and `vue-router`.

A Supabase project (the shop, or the blog with Supabase) does not ship `shared/types/supabase.ts`. Git ignores it. In development, the server writes the generated database types to this file after it applies the migrations.

## `app.vue`

`app.vue` wraps the app in `PlutoRoot`.

```vue [app/app.vue]
<template>
  <PlutoRoot>
    <NuxtPage />
  </PlutoRoot>
</template>
```

`PlutoRoot` includes the admin navbar, `NuxtLayout`, `NuxtLoadingIndicator`, and the base styles.

## `nuxt.config.ts`

The config extends the layer for the template. This example shows the core blog template:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [['@plutocms/core', { install: true }]],
  css: ['~/assets/css/tailwind.css']
})
```

The CMS is on by default. The `plutoGithub` options have defaults: the storage depends on the mode, and Pluto finds the repository from the environment. The real template sets them from environment variables. See [GitHub CMS reference](/docs/github-cms/reference).

## The CSS entry

The app owns the only Tailwind build. The CSS entry starts with three imports:

```css [app/assets/css/tailwind.css]
@import 'tailwindcss';
@import '@nuxt/ui';
@import '#build/pluto.css';
```

Add your own `@theme` after these lines. See [Styles](/docs/core/styles).

## The admin routes

Core owns the `/admin` routes. They need no page files in your app.

| Route | Purpose |
| --- | --- |
| `/admin` | Redirects to `/admin/home` |
| `/admin/home` | The dashboard |
| `/admin/login` | The sign-in page |
| `/admin/no-access` | The page for a signed-in user with no capability |
| `/admin/settings` | The settings pages |
| `/admin/content/<type>` | The generated list, new, and edit pages of a content type |
