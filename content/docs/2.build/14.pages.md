A page is a title, a path, a description, and a body that you edit with the [block editor](/docs/extend/edit-pages-visually). Use pages for the parts of a site that are not posts or products: About, Contact, Terms.

Pages work with every backend. They are off by default.

## Turn pages on

Set `plutoPages.enabled` in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  plutoPages: {
    enabled: true,
  },
})
```

The option is one switch for every backend. The admin then has a **Pages** page. The content type `page` is public in the [Public API](/docs/build/public-api).

With a Supabase backend, also apply migrations `013_pages` and `014_page_layout`. See [Migrations](/docs/supabase/migrations#migration-013).

## Add the route

Pluto does not add a public route for pages. Add a catch-all route to your app. It reads the path from the URL, and it shows the page.

```vue [app/pages/[...path].vue]
<script setup lang="ts">
const route = useRoute()

const path = computed(() => {
  const value = route.params.path
  return Array.isArray(value) ? value.join('/') : String(value)
})

const { page, draft } = await usePage(path)
</script>

<template>
  <article v-if="page">
    <p v-if="draft">This page is a draft.</p>
    <h1>{{ page.title }}</h1>
    <PlutoBlocks :value="page.blocks" />
  </article>
</template>
```

A catch-all route has the lowest priority. A route such as `app/pages/posts/[slug].vue` still wins for its own paths.

## What a page has

| Field | Meaning |
| --- | --- |
| Title | The title of the page. It is required. |
| Path | The whole path, such as `about` or `about/team`. A path can have more than one segment. It is unique. |
| Description | A short text for the page and for search engines. |
| Layout | `default` or `full`. See [The layout of a page](#the-layout-of-a-page). |
| Body | The blocks of the page. The editor has the field `widget: 'blocks'`. |
| Status | Draft or published. |

A page has a draft state, and a trash. Only a published page shows to visitors. A draft answers 404, except to an editor. See [Public API](/docs/build/public-api).

## Where pages live

| Backend | Where |
| --- | --- |
| [Git CMS](/docs/git-cms) | A Markdown file in `content/pages/<path>.md`. The path `about/team` is the file `content/pages/about/team.md`. |
| [Supabase](/docs/supabase) | A row of the table `public.pages`. The column `slug` holds the whole path. |

On the Git CMS, a save is a commit. A page file looks like this:

```md [content/pages/about.md]
---
title: About
description: Who we are.
status: published
---

::note
We are a small team.
::
```

## The layout of a page

The `layout` field has two values:

| Value | Shows |
| --- | --- |
| `default` | The title, the description, and a narrow body. |
| `full` | The blocks only, at the full width. A landing page uses it. |

A page without the field is `default`. `usePage` gives `page.layout`. Your route decides what each value looks like. The route below shows the title in a container for `default`, and only the blocks for `full`. It uses `definePageMeta({ layout: 'full' })`, so the layout of your app adds no container of its own.

```vue [app/pages/[...path].vue]
<script setup lang="ts">
definePageMeta({
  layout: 'full',
})

const route = useRoute()

const path = computed(() => {
  const value = route.params.path
  return Array.isArray(value) ? value.join('/') : String(value)
})

const { page } = await usePage(path)

const full = computed(() => page.value?.layout === 'full')
</script>

<template>
  <PlutoBlocks v-if="page && full" :value="page.blocks" tag="div" />

  <article v-else-if="page" class="container">
    <h1>{{ page.title }}</h1>
    <PlutoBlocks :value="page.blocks" />
  </article>
</template>
```

The `layout: 'full'` of `definePageMeta` is a Nuxt layout of your app, `app/layouts/full.vue`. It is not the field of the page. Make it as your site needs, for example with no container.

On the Git CMS, the field is a `layout:` line in the front matter. On Supabase, it is the column `pages.layout`, from migration `014_page_layout`. The [blocks layer](/docs/layers/blocks) and the [WordPress import](/docs/start-here/coming-from-wordpress) use `full`.

## Capabilities

An admin has every capability. Give the others to a role, or, on the Git CMS, to a GitHub user with push access.

| Capability | Allows | Git CMS | Supabase |
| --- | --- | --- | --- |
| `pages:read_drafts` | Read the drafts, and see a draft on the site. | Yes | Yes |
| `pages:write` | Create and edit pages, as a draft or in review. | No | Yes |
| `pages:publish` | Publish a page. | Yes | Yes |
| `pages:delete` | Move a page to the trash, and delete it for good. | Yes | Yes |

On the Git CMS, a user with push access has `pages:read_drafts`, `pages:publish`, and `pages:delete`. On Supabase, the migration does not give these capabilities to any role. Give them in the **Roles** editor. See [Users and roles](/docs/supabase/users-and-roles).

On Supabase, a page also has the statuses review and scheduled. A scheduled page goes live at its time.

## `usePage`

`usePage(path)` reads one published page. The path is a string, a ref, or a getter. It returns the refs of `useFetch`, and:

| Key | Value |
| --- | --- |
| `page` | The page: `id` (the path), `title`, `description`, `layout`, `blocks`, and the dates. |
| `draft` | `true` when an editor sees a draft. |

It does four things for the page:

- A missing page, or a draft, shows the error page with a 404. Pass `{ notFound: 'null' }` to handle it yourself.
- It sets the title, the description, and the SEO tags. Pass `{ seo: false }` to set your own.
- It shows **Edit Page** in the admin bar for an editor. Pass `{ editLink: false }` to turn it off.
- An editor sees a draft before it is out. Pass `{ drafts: false }` to show published pages only.

## `PlutoBlocks`

`PlutoBlocks` renders the `blocks` of a page. It renders on the server, with the components of `app/components/content/`. See [Components](/docs/build/components#plutoblocks).

## Pages in the public API

A page is a content type. Read it at `/api/pluto/v1/content/page/<path>`. The answer has `blocks`, a document that any stack can render. See [Public API](/docs/build/public-api#the-blocks-of-an-item).
