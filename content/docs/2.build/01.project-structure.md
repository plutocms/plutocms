A Pluto project is a Nuxt app. It extends one or more layers.

## The blog template

The blog template works with both backends: the Git CMS (no database) and Supabase. With the Git CMS, it has these files:

::pluto-file-tree
---
tree: |
  app/
    assets/css/main.css  # The look of the site, light and dark
    components/
      PlutoPostPreview.vue  # The preview in the post editor
      PostArticle.vue  # One post
      PostListItem.vue  # One post in the list
      PostNavigation.vue  # The older and the newer post
      SiteFooter.vue
      SiteNavbar.vue
    layouts/default.vue
    pages/  # The public pages
      index.vue
      posts/[slug].vue
    app.vue
    error.vue
  content/
    posts/  # The posts, as Markdown files (Git CMS only)
      hello-world.md
  public/
    favicon.svg
  .gitignore
  nuxt.config.ts
  package.json
  README.md
  tsconfig.json
---
::

- `content/posts/` holds the posts as Markdown files (Git CMS only).
- `app/pages/` holds the public pages. They read posts with `usePosts`, `usePost` and `useAdjacentPosts`. See [Public API](/docs/build/public-api#in-a-nuxt-site).
- `app/components/PostArticle.vue` renders one post, with the core component `PlutoHtml` for the body. The post page and the preview of the post editor (`PlutoPostPreview.vue`) both use it.
- `main.css` is the whole look, in plain CSS: the colors as variables for light and dark, and the post body (`.pluto-prose`). Each color is also a Tailwind class, for example `text-heading`, `text-muted` and `border-line`. The template uses no UI library and no Pluto styles. To use them, see [Styles](/docs/build/styles).
- The site starts in light mode (`colorMode.preference` in `nuxt.config.ts`). `ColorModeButton` of core in the navbar switches it.
- The texts are in English, in the files. For a site in more than one language, see [Internationalization](/docs/build/i18n).
- `nuxt.config.ts` extends `@plutocms/core` and, when needed, sets the `plutoGithub` options.
- `package.json` lists `@plutocms/core`, `nuxt`, `vue`, and `vue-router`. No other layer is needed.

With Supabase, three things differ, and the CLI sets them:

- `nuxt.config.ts` extends `@plutocms/supabase-blog`. That layer brings `@plutocms/supabase` and core.
- `package.json` also lists `@plutocms/supabase-blog`, and has the `supabase-types` script.
- There is no `content/` folder: the posts are in the database.

The pages link to a post by its slug (`/posts/<slug>`), the same for both backends.

The template has no `.env` file. The CLI writes it when you create the project. With the Git CMS, **Create the GitHub App** in the admin gives the GitHub App values. See [Deploy](/docs/start-here/deploy).

## The shop template

The shop template (Supabase) has these files:

::pluto-file-tree
---
tree: |
  app/
    assets/css/tailwind.css  # The CSS entry of the app
    components/
      LanguageSwitch.vue
      ProductCard.vue
    layouts/default.vue
    pages/  # The public pages
      index.vue  # The product list
      product/[slug].vue  # One product
    utils/product.ts
    app.config.ts
    app.vue
    error.vue
  i18n/locales/
    en.json
    pt-BR.json
  public/
    favicon.ico
    robots.txt
  .gitignore
  nuxt.config.ts
  package.json
  README.md
  tsconfig.json
---
::

Its `nuxt.config.ts` extends `@plutocms/supabase-shop` and the [3D add-on](/docs/layers/3d) `@plutocms/3d`, so a product can have a 3D model. The shop layer brings `@plutocms/supabase` and core.

## The Dashboard only template

The Dashboard only template has no public site:

::pluto-file-tree
---
tree: |
  app/
    app.vue
  .env.example
  .gitignore
  nuxt.config.ts  # Sends / to /admin
  package.json
  README.md
  tsconfig.json
---
::

It has no CSS entry: it has no public pages, and the admin has its own CSS. See [Styles](/docs/build/styles).

A Supabase project (the shop, or the blog with Supabase) does not ship `shared/types/supabase.ts`. Git ignores it. In development, the server writes the generated database types to this file after it applies the migrations.

## `app.vue`

`app.vue` wraps the app in `PlutoRoot`.

```vue [app/app.vue]
<template>
  <PlutoRoot>
    <NuxtPage />
  </PlutoRoot>
</template>
```

`PlutoRoot` includes the admin navbar, `NuxtLayout`, `NuxtLoadingIndicator`, and the base styles.

## `nuxt.config.ts`

The config extends the layer for the template. This example shows the core blog template:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@plutocms/core'],
  css: ['~/assets/css/main.css']
})
```

The CMS is on by default. The `plutoGithub` options have defaults: the storage depends on the mode, and Pluto finds the repository from the environment. The template sets no `plutoGithub` option: the defaults are enough. See [Git CMS reference](/docs/git-cms/reference).

## The CSS entry

The admin has its own CSS, so this file is for your site only. The blog template uses Tailwind and no UI library:

```css [app/assets/css/main.css]
@import 'tailwindcss';
```

A site on Nuxt UI, such as the shop template, also imports Nuxt UI and the Pluto CSS:

```css [app/assets/css/tailwind.css]
@import 'tailwindcss';
@import '@nuxt/ui';
@import '@plutocms/css';
@import '@plutocms/css/base';
```

`@plutocms/css/base` gives the look of the [Pluto components](/docs/build/components), such as `PlutoHtml`. Add your own `@theme` after these lines. See [Styles](/docs/build/styles).

## The admin routes

Core owns the `/admin` routes. They need no page files in your app.

| Route | Purpose |
| --- | --- |
| `/admin` | Redirects to `/admin/home` |
| `/admin/home` | The dashboard |
| `/admin/login` | The sign-in page |
| `/admin/no-access` | The page for a signed-in user with no capability |
| `/admin/not-configured` | The page that shows in production when no backend registers an auth driver |
| `/admin/media` | The media library, when the backend has a media driver |
| `/admin/settings` | The settings pages |
| `/admin/content/<type>` | The generated list, new, and edit pages of a content type |
