If you know WordPress, you know most of Pluto already. This page maps the WordPress words to the Pluto words. Then it shows how to import your Elementor pages.

## The concept map

| In WordPress | In Pluto | Read |
| --- | --- | --- |
| A post type | A content type | [Add a content type](/docs/build/add-a-content-type) |
| A plugin | A layer | [How layers work](/docs/extend/layers) |
| ACF fields | The fields of a content type | [Content model](/docs/reference/content-model) |
| An options page | A singleton type | [Singleton types](/docs/reference/content-model#singleton-types) |
| Yoast | `@plutocms/seo` | [SEO](/docs/layers/seo) |
| Elementor pages | Pages made of blocks | [Blocks](/docs/layers/blocks) and [Pages](/docs/build/pages) |
| A menu | Coming. For now, a menu is part of the code of your site. | [Project structure](/docs/build/project-structure) |
| A theme | A template | [Templates](/templates) |

A layer is a Nuxt layer that you add to your app. You install it with your package manager. You do not install it in the admin.

## Import Elementor pages

`@plutocms/wordpress` is a command line tool. It reads a WordPress export and writes your Elementor pages as Pluto pages. Each page is made of the [blocks](/docs/layers/blocks) of `@plutocms/blocks`, with `layout: full`.

The tool aims for the same look, not a pixel copy. A value that is not in the scale of the blocks rounds to the nearest step. The report lists each change.

It writes to a [Git CMS](/docs/git-cms) project. It needs Node 20 or a newer version. You do not install it.

::steps{level="3"}

### Export from WordPress

You have two choices:

- **All pages:** in WordPress, open **Tools > Export**, choose **All content**, and download the file. It is a `.xml` file.
- **One page:** in Elementor, open **Templates > Saved Templates**, and choose **Export** on the page. It is a `.json` file.

The `.xml` file also has the Elementor kit, so the tool can build your theme from it. A `.json` file of one page has no kit.

### Start a Pluto site

Create a site with the blog template, or start from scratch. Both use the Git CMS. See [Quickstart](/docs/start-here/quickstart) and [CLI](/docs/reference/cli). The blog template already turns pages on and has a route for them: add the blocks layer. From scratch, also turn pages on and add a page route (see [Pages](/docs/build/pages)).

Add the blocks layer, with pages on:

:pluto-install{name="@plutocms/blocks"}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@plutocms/core', '@plutocms/blocks'],
  plutoPages: {
    enabled: true,
  },
})
```

Your site needs a route for pages. See [Pages](/docs/build/pages#add-the-route). A page of the import has `layout: full`, so the route must honor it. See [The layout of a page](/docs/build/pages#the-layout-of-a-page).

### Run a dry run

Run the tool in the folder of your Pluto project, or give the folder with `--out`. A dry run writes nothing and downloads nothing. It prints the plan and the report.

```bash [Terminal]
npx @plutocms/wordpress import export.xml --out ./my-pluto-site --dry-run
```

Read the output. Then run the same command without `--dry-run`:

```bash [Terminal]
npx @plutocms/wordpress import export.xml --out ./my-pluto-site
```

The tool writes these files:

| File | Content |
| --- | --- |
| `content/pages/<path>.md` | One file for each Elementor page. The path of the page is the slug, with the slugs of its parents. The front page is `home`. |
| `content/media/<id>.md` | One record for each image. |
| `public/media/<yyyy>/<mm>/<file>` | The image files. |
| `pluto-import/theme.json` | The theme, from the Elementor kit. |
| `pluto-import/media.json` | The source URL of each image. A new run reuses it. |
| `pluto-import-report.md` | The report. |

A published page in WordPress is published in Pluto. Any other status is a draft. A page from a `.json` file is a draft.

To run it again, use the same command. The tool skips a page that it already imported. Add `--force` to write the page again.

### Add the theme and the fonts

The tool does not change your `app.config.ts`. It prints the theme as a snippet, and it saves the snippet in `pluto-import/theme.json`. Paste the snippet in your `app.config.ts`:

```ts [app/app.config.ts]
export default defineAppConfig({
  plutoBlocksTheme: {
    colors: {
      primary: '#EF5777',
      secondary: '#51C9C0',
      text: '#222F3E',
      accent: '#222F3E',
    },
    fonts: {
      heading: '"Playfair Display", serif',
      body: '"Work Sans", sans-serif',
    },
  },
})
```

The tool does not install fonts. The report lists the Google fonts of your pages, with a snippet for `@nuxt/fonts`. Add the module, and paste the snippet in `nuxt.config.ts`. See the [theme](/docs/layers/blocks#theme) of the blocks.

### Read the report

Open `pluto-import-report.md`. It has:

- the counts: pages imported, skipped and not written, and images downloaded, reused and failed;
- for each page: the placeholders, the values that were rounded, the responsive values that were dropped, the icons with no match and the images with no alt text;
- what was not imported: headers, footers and saved templates;
- the images that did not download, with the reason;
- the theme snippet, and the fonts.

Fix each placeholder in the [block editor](/docs/extend/edit-pages-visually). Add the missing alt text there too.

::

## The options

```text
pluto-wordpress import <file.xml|page.json> [--out <dir>] [--dry-run] [--no-media] [--force]
```

| Option | Meaning |
| --- | --- |
| `<file>` | The WordPress export (`.xml`), or the JSON of one Elementor page (`.json`). |
| `--out <dir>` | The Pluto project folder. The default is the current folder. |
| `--dry-run` | Writes nothing and downloads nothing. Prints the plan and the report. |
| `--no-media` | Keeps the remote image URLs. Downloads nothing. |
| `--force` | Writes a page again, even when its file is already there. |

The tool downloads only `http` and `https` images, up to 20 MB each. It refuses an SVG, because the media library does not allow it. An image that fails keeps its remote URL, and the report lists it.

## What is not imported yet

- Shortcodes. A shortcode becomes a placeholder text block.
- Elementor Pro widgets and add-on widgets. They become placeholders.
- Headers, footers and menus. The report lists the headers, footers and saved templates.
- Pages that are not built with Elementor.
- Forms, redirects, posts and users.
- Values for tablet and phone. The tool drops them, and the report counts them.
- Supabase sites. The tool writes only to a Git CMS project.
