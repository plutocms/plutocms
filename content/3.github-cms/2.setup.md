## Options

Set the options under `plutoCms` in `nuxt.config.ts`.

| Option | Default | Rule |
| --- | --- | --- |
| `enabled` | `false` | Turns the CMS on. |
| `storage` | `'github'` | `'github'` or `'fs'`. `'fs'` is valid in development only. |
| `github.repo` | none | `owner/name`. Required when storage is `github`. |
| `github.branch` | `'main'` | The branch to read and commit to. |
| `github.appSlug` | `''` | The slug of the GitHub App. |
| `github.apiUrl` | `'https://api.github.com'` | The API base URL. |
| `dir` | `'content'` | A relative path. No `..`, no leading `/`, no drive letter. The module changes `\` to `/` and removes a trailing `/`. |
| `commit.skipDeploy` | `true` | Adds a `[skip ci]` marker to the commit messages. A site that must redeploy on each edit, such as a docs site, sets it to `false`. |
| `cache.headTtl` | `60` | Seconds. Zero or more. |
| `cache.storage` | `'cache'` | The Nitro storage mount for the cache. |
| `cache.publicMaxAge` | `60` | Seconds. Zero or more. The `s-maxage` of the public read routes. |
| `postType` | `true` | Registers the fixed post content type, on the server and on the client. With `false`, the admin does not show Posts and does not register the post capabilities. A layer that brings its own types sets it to `false`. |

A bad option turns the CMS off and logs an error. The module does not throw.

## Environment variables

The secrets are run-time variables. The module does not check them at build time. Set them as `NUXT_PLUTO_CMS_<NAME>`.

| Variable | Required | Value |
| --- | --- | --- |
| `NUXT_PLUTO_CMS_SESSION_PASSWORD` | Yes | 32 characters or more, random. |
| `NUXT_PLUTO_CMS_GITHUB_APP_ID` | Yes | The App ID. |
| `NUXT_PLUTO_CMS_GITHUB_CLIENT_ID` | Yes | The Client ID. |
| `NUXT_PLUTO_CMS_GITHUB_CLIENT_SECRET` | Yes | The client secret. |
| `NUXT_PLUTO_CMS_GITHUB_PRIVATE_KEY` | Yes | The PEM. Literal `\n` escapes are fine. |
| `NUXT_PLUTO_CMS_GITHUB_READ_TOKEN` | No | A read-only token. It replaces the installation token for anonymous reads. |
| `NUXT_PLUTO_CMS_ALLOWED_USERS` | No | GitHub logins, comma-separated, without case. When set, only these users can sign in, even with push access. |

The module puts a non-secret copy of `enabled`, `repo`, `branch`, `appSlug`, `storage`, `dir`, and `postType` in `runtimeConfig.public.plutoCms`.

## The template config

The core blog template reads the repository settings from environment variables:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [[process.env.PLUTO_PLUTO_PATH || '@plutocms/pluto', { install: true }]],
  plutoCms: {
    enabled: true,
    storage:
      process.env.PLUTO_CMS_STORAGE === 'github' || process.env.NODE_ENV === 'production'
        ? 'github'
        : 'fs',
    github: {
      repo: process.env.PLUTO_CMS_REPO,
      branch: process.env.PLUTO_CMS_BRANCH || 'main',
      appSlug: process.env.PLUTO_CMS_APP_SLUG
    },
    dir: 'content'
  }
})
```

| Variable | Value |
| --- | --- |
| `PLUTO_CMS_REPO` | `owner/name` of the repository |
| `PLUTO_CMS_BRANCH` | Optional. The default is `main`. |
| `PLUTO_CMS_APP_SLUG` | The URL name of the GitHub App |
| `PLUTO_CMS_STORAGE` | Set to `github` to test against GitHub in development |

## Develop with local files

In development, the template uses `storage: 'fs'`. The dev server reads and writes the local `content/` folder. It never writes to the real repository.

Open `http://localhost:3000/admin`. On your machine, you are signed in as a fixed local user with all capabilities. No GitHub step is needed.

The `fs` store uses the project directory as the root, so a post is at `<project>/content/posts/<slug>.md`.

::note
The dev local user works only for a request from your machine. A request with `x-forwarded-for` or `forwarded` is not local. A request whose `Host` is not `localhost`, `127.0.0.1`, or `[::1]` is not local either. A tunnel or a DNS-rebinding page gets no access.
::

## Deploy

Deploy to a host with a server runtime, such as Vercel, Netlify, or Node. The site reads the posts at run time, so a static export does not work. See [Deploy to Vercel](/guides/deploy-to-vercel).

## Commits

Commit messages have this form. `<type>` is the name of the content type. For the built-in type, it is `post`.

- `content(<type>): create "slug"`
- `content(<type>): update "slug"`
- `content(<type>): publish "slug"` and `unpublish`
- `content(<type>): rename "a" -> "b"`
- `content(<type>): delete "slug"`

A save that changes nothing makes no commit.

With `commit.skipDeploy` on, a `[skip ci]` marker ends the message. A host that honors the marker does not rebuild on each save. Not every host reads this marker. Test it on your host.

## Cache

The store keeps these in a cache:

- The head of the branch, for `cache.headTtl` seconds.
- The directory index, by `<dir>@<headOid>`.
- The tree index of a nested type, by head.
- The parsed files, by blob id.
- The rendered HTML and the excerpts, by blob id.

A blob id never changes, so a blob entry never goes stale. The default backend is a `Map`. With `cache.storage`, the cache uses a Nitro storage mount.

## GitHub Enterprise Server

Set `plutoCms.github.apiUrl` to `https://<host>/api/v3`. The OAuth pages use `https://<host>`. Any other API URL uses `https://github.com`.

## Rate limits

When GitHub rate limits a call, the CMS answers 503 with a `Retry-After` header.
