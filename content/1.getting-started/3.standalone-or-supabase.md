Pluto has two modes. Choose the mode when you create the project.

## Standalone mode

`@plutocms/pluto` can run on its own. It needs no database and no other layer.

- Posts are Markdown files in a GitHub repository.
- Editors write them in the Pluto admin.
- Each save is a commit.
- The public site reads the posts from GitHub at run time, with a cache. A save publishes in seconds, with no new build.
- Users with push access to the repository are editors. They sign in with a GitHub App.

The standalone CMS is off by default. You turn it on with `plutoCms.enabled`. It refuses to run next to the supabase layer.

Use this mode for a Markdown blog. See [GitHub CMS](/github-cms).

## Supabase mode

The supabase layer gives Pluto a database and sign-in.

- Supabase provides the Postgres database, the auth, and the storage.
- Roles and capabilities live in the database.
- Admins invite users and edit roles in the admin.
- Feature layers add a shop, a blog, and a media library.

Use this mode for a shop, or for a site with many users and roles. See [Supabase](/supabase).

## Compare the modes

| | Standalone | Supabase |
| --- | --- | --- |
| Database | None | Supabase (Postgres) |
| Content storage | Markdown files in GitHub | Database tables |
| Sign-in | GitHub App | Supabase auth, email and password |
| Who can edit | Users with push access to the repository | Users with a role |
| Template | `core-blog` | `supabase-blog`, `supabase-shop` |
| Drafts | `status: draft` in the frontmatter | A `status` column |

::warning
You cannot mix the two modes. If you enable the standalone CMS with the supabase layer, the module logs an error and stays off.
::

## Use Pluto in an existing Nuxt project

You do not need a template. Extend the layers in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '@plutocms/pluto'
    // Then add any backend or feature layers you need.
  ]
})
```

Order matters. A feature layer goes after the layers that it needs. For example, `@plutocms/supabase-shop` goes after `@plutocms/pluto` and `@plutocms/supabase`.

Your app also needs one CSS entry with the Pluto imports. See [Styles](/core/styles).
