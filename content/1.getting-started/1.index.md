Pluto CMS is a layer-based CMS. It runs on [Nuxt](https://nuxt.com/).

You do not install one big system. You install a core layer. Then you add the layers that you need.

::warning
Pluto CMS is in **alpha**. Expect breaking changes, incomplete features, and rough edges. npm is not supported, because the layer dependencies do not install correctly with it. Use **pnpm** or **bun**.
::

## Main ideas

- **Layers.** Pluto uses Nuxt layers. Each layer has one job.
- **Opt-in features.** A layer adds its features only when you extend it.
- **TypeScript first.** The contracts of Pluto are typed.
- **Two modes.** Pluto runs with no database, or on top of Supabase.
- **Headless use.** The admin can run as a separate app. Your data is available through composables and REST routes.

## The layers

| Layer | Package | Job |
| --- | --- | --- |
| Core | `@plutocms/pluto` | The admin shell, the content model, the extension registry, mail, i18n. It also holds the GitHub CMS. |
| Supabase | `@plutocms/supabase` | Supabase database, auth, users, roles, and migrations. |
| Shop | `@plutocms/supabase-shop` | Products and a product media gallery. |
| Blog | `@plutocms/supabase-blog` | Blog posts with a rich text editor. |
| Storage | `@plutocms/supabase-storage` | A media library on Supabase Storage. |
| UI | `@plutocms/ui` | Shared Vue components. |
| Utils | `@plutocms/utils` | Shared helpers. |

A feature layer depends on a backend layer. For example, `@plutocms/supabase-shop` needs `@plutocms/supabase`.

## Requirements

- Node.js 22 or newer, or Bun.
- pnpm or Bun.
