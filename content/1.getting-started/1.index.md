Pluto is a layer-based CMS. Its admin and its API run on [Nuxt](https://nuxt.com/). Your site can be the same Nuxt app, or a site in any other framework or stack that reads the content through the API. See [Use Pluto headless](/guides/use-pluto-headless).

You do not install one big system. You install a core layer. Then you add the layers that you need.

::warning
Pluto is in **alpha**. Expect breaking changes, incomplete features, and rough edges.
::

## Main ideas

- **Layers.** Pluto uses Nuxt layers. Each layer has one job.
- **Opt-in features.** A layer adds its features only when you extend it.
- **TypeScript first.** The contracts of Pluto are typed.
- **Two modes.** Pluto runs with no database, or on top of Supabase.
- **Data access.** A Nuxt site reads its data through composables. A site in any stack reads it through the [Public API](/core/public-api).

## The layers

| Layer | Package | Job |
| --- | --- | --- |
| Core | `@plutocms/pluto` | The admin shell, the content model, the extension registry, mail, i18n. It also holds the GitHub CMS. |
| Supabase | `@plutocms/supabase` | Supabase database, auth, users, roles, and migrations. |
| Shop | `@plutocms/supabase-shop` | Products and a product media gallery. |
| Blog | `@plutocms/supabase-blog` | Blog posts with a rich text editor. |
| Storage | `@plutocms/supabase-storage` | A media library on Supabase Storage. |
| Nuxt Content | `@plutocms/nuxt-content` | An admin editor for the pages of a Nuxt Content site. It builds on the GitHub CMS. |
| Utils | `@plutocms/utils` | Shared helpers. |

A layer brings the layers that it builds on. For example, `@plutocms/supabase-shop` extends `@plutocms/supabase`, which extends `@plutocms/pluto`. Your app extends only the top layer that it uses. See [Layers](/core/layers).

## Requirements

- Node.js 22 or newer, or Bun.
- A package manager: npm, pnpm, yarn, Bun, or Deno. The CLI asks which one to use.
