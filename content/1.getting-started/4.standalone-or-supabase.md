Pluto has two modes. Choose the mode when you create the project.

## Standalone mode

`@plutocms/core` can run on its own. It needs no database and no other layer.

- Posts are Markdown files in a Git repository.
- Editors write them in the Pluto admin.
- Each save is a commit. In development, it is a commit in your local repository, with no GitHub step. A deployed site commits to GitHub.
- The deployed site reads the posts from GitHub at run time, with a cache. A save publishes in seconds, with no new build.
- Users with push access to the repository are editors. They sign in with a GitHub App.

The standalone CMS is on by default (`plutoGithub.enabled: 'auto'`) when no backend layer is present. It stays off next to the supabase layer.

Use this mode for a Markdown blog. See [GitHub CMS](/github-cms).

## Supabase mode

The supabase layer gives Pluto a database and sign-in.

- Supabase provides the Postgres database, the auth, and the storage.
- Roles and capabilities live in the database.
- Admins invite users and edit roles in the admin.
- Feature layers add a shop, a blog, and a media library.

Use this mode for a shop, or for a site with many users and roles. See [Supabase](/supabase).

## Compare the modes

| | Standalone | Supabase |
| --- | --- | --- |
| Database | None | Supabase (Postgres) |
| Content storage | Markdown files in Git (local Git in development, GitHub when deployed) | Database tables |
| Sign-in | GitHub App | Supabase auth, email and password |
| Who can edit | Users with push access to the repository | Users with a role |
| Template | `-t blog --backend github` | `-t blog --backend supabase`, `-t shop` |
| Drafts | `status: draft` in the frontmatter | A `status` column |

::warning
You cannot mix the two modes. With the supabase layer, the default `'auto'` keeps the standalone CMS off and logs nothing. If you set `plutoGithub.enabled: true` with the supabase layer, the module logs an error and stays off.
::

## Use Pluto in an existing Nuxt project

You do not need a template. Extend one layer in `nuxt.config.ts`. Extend the top layer that you use. It brings the layers below it.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // For Supabase, use '@plutocms/supabase' or a feature layer such as
  // '@plutocms/supabase-shop' instead of '@plutocms/core'.
  extends: [['@plutocms/core', { install: true }]]
})
```

Do not list the layers below the top layer. For example, `@plutocms/supabase-shop` already extends `@plutocms/supabase`, which extends `@plutocms/core`. The `package.json` of your app needs only the top layer, plus `nuxt`, `vue`, and `vue-router`. See [Layers](/core/layers).

Your app also needs one CSS entry with the Pluto imports. See [Styles](/core/styles).
