The `create-pluto` command makes a new project from a template, installs the dependencies, and tells you how to start it.

## Run the CLI

::code-group
```bash [npm]
npm create pluto@latest
```

```bash [pnpm]
pnpm create pluto@latest
```

```bash [bun]
bun create pluto@latest
```
::

## The wizard

The wizard asks these things, in this order:

1. **Project directory.** The default is `my-pluto-project`. The CLI makes the directory if it does not exist.
2. **Website title.** The default is `My Awesome Website`.
3. **Database provider.** Choose `Supabase` or `None (Markdown files in Git)`. With `None`, the CLI also makes the project a Git repository: in development, each save in the admin is a commit in it.
4. **Supabase values.** Only for Supabase. See [With Supabase](#with-supabase).
5. **Template.** The list shows only the templates that the database allows.
6. **Package manager.** `npm`, `pnpm`, `yarn`, `bun` or `deno`. The default is the one that runs the CLI.

| Database | Templates |
| --- | --- |
| Supabase | `Shop`, `Blog` |
| None (Markdown files in Git) | `Blog` |

If the database has only one template, the wizard picks it for you.

Then the CLI downloads the template, writes `.env`, and installs the dependencies. At the end, it shows the next steps:

```text [Terminal]
◇  Next steps
│  cd my-pluto-project
│  npm run dev
│
│  Then open http://localhost:3000/admin
└  Docs: https://pluto.vulmix.dev/getting-started/create-a-project
```

The dev command follows the package manager: `pnpm run dev`, `bun run dev`, `deno task dev`, and so on.

Before the download, the wizard checks two things. If `nuxt.config.ts` exists in the current directory, the wizard asks "Nuxt project detected. Do you want to add Pluto environment variables?". If the target directory is not empty, the wizard asks for confirmation.

You can cancel at any prompt.

## Skip the prompts

| Option | What it does |
| --- | --- |
| `<folder>` (first argument) | The project directory. |
| `-t`, `--template` | A template shortcut. It skips the database and template prompts. |
| `--pm`, `--package-manager` | The package manager. It skips that prompt. |
| `--no-install` | Do not install the dependencies. The next steps then show the install command. |

```bash [Terminal]
npm create pluto@latest my-blog -t core-blog --pm pnpm
```

The shortcut has two parts: `<database>-<template>`.

| Shortcut | Meaning |
| --- | --- |
| `supabase-shop` | Supabase and the shop template |
| `supabase-blog` | Supabase and the blog template |
| `core-blog` | No database and the blog template |

The `core` database has only the `blog` template. A shortcut such as `core-shop` is not valid. An unknown shortcut or package manager is also not valid. The CLI then prints the available options and exits with status 1.

In a script (no terminal), the CLI does not ask for the website title or the package manager. It uses the defaults. So `create-pluto my-blog -t core-blog --pm bun` runs with no question.

## What the CLI writes

The CLI downloads the template from GitHub with `giget`:

```text
gh:plutocms/pluto-<database>-<template>-template
```

Then it writes a `.env` file. If `.env` exists, the CLI merges the new values into it. Each value is quoted.

The CLI always writes the website title:

- `WEBSITE_NAME` for the Supabase templates.
- `NUXT_PUBLIC_WEBSITE_NAME` for the `core` template.

### With Supabase

The CLI asks for three values. It checks each one.

| Prompt | Variable |
| --- | --- |
| Supabase URL | `SUPABASE_URL` |
| Supabase key | `SUPABASE_KEY` |
| Database connection string (`postgres://` or `postgresql://`) | `DATABASE_URL` |

You need a Supabase project first. You can make one at [database.new](https://database.new/). Find the connection string in the Supabase dashboard: Project Settings, Database, Connection string. The pooler connection string also works.

### With the core template

The CLI asks nothing about GitHub. It writes `NUXT_PLUTO_GITHUB_SESSION_PASSWORD`, a random value with 43 characters.

You make the GitHub App later, from the admin of your site:

- **On your machine,** you need no App. The dev server signs you in as a local user and edits the files in `content/`.
- **After a deploy,** open `/admin/login` and select **Create the GitHub App**. See [GitHub CMS in 10 minutes](/github-cms/quickstart).

## Start the dev server

Run the commands of the next steps. Then open `http://localhost:3000/admin`.

With the core template, the dev server reads and writes the local `content/` folder. On your machine, you are signed in as a local user. See [GitHub CMS](/github-cms).

::note
A normal project uses the npm packages and needs no setup for local layers. The `plutoLayer` helper and `PLUTO_LOCAL_ROOT` are for people who work on Pluto itself. See [Local layers](/contributing/workspace#local-layers).
::
