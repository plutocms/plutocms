`@plutocms/supabase` is the backend layer for Supabase. It gives Pluto a database, sign-in, users, roles, and database migrations.

## What the layer gives

- An auth driver for the admin shell. See [Auth](/supabase/auth).
- Versioned database migrations that an admin applies from the admin UI. See [Migrations](/supabase/migrations).
- Roles and capabilities in the database, and server guards. See [Users and roles](/supabase/users-and-roles).
- A content adapter for the generic content routes. See [Content adapter](/supabase/content-adapter).
- A stored admin language for each user. See [Profile language](/supabase/profile-language).
- Admin pages in English and Brazilian Portuguese.

## Install

::note
You need a Supabase project. You need the project URL and the publishable key. Find them in the [Supabase dashboard](https://supabase.com/dashboard).
::

::steps{level="3"}

### Set the environment variables

Add these variables to the `.env` file in the root of your project:

```env [.env]
SUPABASE_URL=your-supabase-url
SUPABASE_KEY=your-publishable-supabase-key
```

### Add the dependencies

```bash [Terminal]
bun add @nuxtjs/supabase supabase
```

### Extend the layer

Add the layer to `extends` in `nuxt.config.ts`. It must come after `@plutocms/pluto`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '@plutocms/pluto',
    '@plutocms/supabase'
  ]
})
```

::

The layer extends `@plutocms/pluto`. The `create-pluto` CLI does these steps for you.

## First run

On a new install, the setup guard sends every admin path to `/admin/setup`. The setup wizard has two steps: **Database Setup** and **Complete Setup**.

1. The wizard asks for a database connection string. The server opens a direct PostgreSQL connection and runs the SQL files of the layers.
2. As the last step, the server writes the connection string to `.env` as `DATABASE_URL`.
3. When the setup is done, the wizard tells you to create your admin account by signing up.

::warning
In development, Nuxt restarts the dev server when `.env` changes. The page can briefly show a reconnecting message. This is expected, not an error.
::

After the setup is done, `/admin/setup` redirects to `/admin/login`.

## API routes

The layer includes API routes for Supabase services:

- `GET /api/settings`
- `POST /api/settings/update`
- `POST /api/auth/signup`
- The access API under `/api/access/**`. See [Users and roles](/supabase/users-and-roles).
- `GET` and `POST /api/profile/locale`. See [Profile language](/supabase/profile-language).
- `GET /api/permissions/me`.
- `GET /api/migrations/status` and `POST /api/migrations/run`.

## Composables

- `useAuth`. It signs in, requests a password reset, and updates the password with Supabase.

## Types

- `Database`. Auto-imported type definitions for Supabase database interactions.

## Settings

The layer stores settings in the `settings` table with free-text, namespaced keys, for example `blog.posts_per_page`. Two settings feed the shell: `website_title` and `website_url`.
