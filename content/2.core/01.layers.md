The core layer is `@plutocms/pluto`. It gives the foundation of the CMS. Other layers plug into it.

## Layer kinds

**Core layer.** It owns the admin shell, the content model, the extension registry, permissions, mail, i18n, and the single Tailwind build.

**Backend layers.** They handle data, authentication, and APIs. `@plutocms/supabase` is the first one. Other providers are possible in the future.

**Feature layers.** They add domain features on top of a backend layer. `@plutocms/supabase-shop` and `@plutocms/supabase-blog` are feature layers.

::note
A feature layer depends on a backend layer. For example, `@plutocms/supabase-shop` needs `@plutocms/supabase`.
::

## What core gives

- `<PlutoRoot>`. It wraps your app in `app.vue`. It includes the admin navbar, `NuxtLayout`, `NuxtLoadingIndicator`, and the base styles.
- `<ColorModeButton>`. A light and dark mode toggle with no configuration.
- The admin shell: the `/admin` route, the `/admin/login` page, the route guard, and the navbar.
- `<PlutoNavbarAdmin>` and `<PlutoNavbarAdminActions>`. They give structure for actions from other layers.
- `definePlutoExtension`. One function that a layer calls to plug into the admin.

## Extend the layers

Add the layers to `extends` in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '@plutocms/pluto',
    '@plutocms/supabase',
    // Add this layer after the Pluto and Supabase layers.
    '@plutocms/supabase-shop'
  ]
})
```

## Use Pluto as a headless CMS

The admin dashboard can run as a standalone app on providers like Vercel or Netlify. You can read the data in two ways:

- With composables, inside a Nuxt app.
- With the REST APIs that the layers expose.
